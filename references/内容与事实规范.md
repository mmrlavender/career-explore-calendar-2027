# 内容与事实规范（career-explore-calendar-2027）

## 一、数据结构

```json
{
  "meta":  { "title": "...", "year": 2027, "school": "...", "days": 365, "start": "...", "end": "...", "lines": {...}, "day_types": {...}, "card_patterns": {...}, "stats": {...} },
  "months": [ { "month": 1, "theme": "...", "cover": "..." } ],
  "days":   [ { "date": "2027-01-01", "month": 1, "day": 1, "weekday": "五", "type": "锚定日", "carry": "...", "question": "...", "hint": "...", "record": "...", "code": "...", "line": "A" } ],
  "major_days": [ { "date": "...", "college": "...", "major": "...", "title": "...", "body": "..." } ],
  "cards":  { "<卡名>": { "...": "..." } }
}
```

字段口径：
- `days[].type` 决定卡片配色与插画（`锚定日 / 归档日 / 专业专属日 / 节气观察 / 季度体检 / 周闭环 / 工具卡日 / 月度成果 / 弹性日`）。
- `days[].line` 为分线缩写：A 升学 / B 就业 / C 创业 / D 考编 / E 参军；不写「术语未定」。
- `major_days[]` 必须与学校在办专业口径一致，学院名一并写全。

## 二、事实纪律（硬约束，写内容与改模板时都适用）

1. 不编造数字：不写薪资区间、不写「缺口 XX 万」「就业率 XX%」「升学率 XX%」，除非有可核对的官方来源并注明。
2. 不承诺结果：不出现「包就业」「保证上岸」「轻松月入过万」。
3. 专业与学院名称以学校公布口径为准，不臆造、不简写混用。
4. 不写内部草稿引用：正文不得出现「见 v5 第 x 节」「详见某文档」「待补」。
5. 分线中立：升学/就业/创业/考编/参军之间只描述路径差异与准备要点，不做优劣比较。
6. 不写个人化断言：面向群体的内容用「可以」「通常」「建议」等限定表达，不写绝对命令式。

## 三、改数据后的必核清单

1. `days` 长度 = 当年天数（2027 为 365），日期连续无缺无重。
2. 星期标注与真实日历一致（`weekday` 用中文单字：一…日）。
3. 题型计数与 `meta.day_types` 一致。
4. `major_days` 数量 = 专业数，且每个专业只出现一次日期。
5. `cards` 数量与被 `days[].type` 引用的卡名闭合，无悬空引用。
6. 全量 JSON 合法性复检：字符串内的引号用中文引号，避免破坏 JSON。
7. 重跑两条构建命令后，网页版页数 42、打印版 15 个 HTML，PDF 页数与「版式与打印说明」基准一致。

## 四、常见内容缺陷

- 月份主题与当月日页内容脱节（改月主题时顺手看本月日页）。
- 节气观察日日期与当年真实节气错位一天。
- 专业专属日只写专业名、没有可执行的一步（应落到「今天能做什么」）。
- 卡片文案与题型不匹配（工具卡写成口号，周闭环写成知识介绍）。
